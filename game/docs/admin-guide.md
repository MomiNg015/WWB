# 后台使用与运维

## 入口与账号

开发入口：http://127.0.0.1:5173/admin 。构建后运行服务也可访问 http://127.0.0.1:3311/admin 。与游戏共用启动命令 npm start；管理员页面和游戏代码分开加载。

首次启动创建用户名 moming，密码使用本次对话指定的临时密码。实现中只保存scrypt哈希，不把明文密码放到前端或仓库文档。账号设置中可修改密码；更改后所有该管理员会话失效，需要重新登录。重复启动不会重置密码。

首次初始化可设置 ADMIN_INITIAL_USERNAME、ADMIN_INITIAL_PASSWORD 覆盖初始账号。这两个变量仅在数据库尚未初始化时使用；不用于覆盖已有管理员密码。无公开注册管理员入口。

## 日常操作

- 用户：搜索名字/ID，查看详情，编辑昵称、积分、场次、状态及已发布角色；填写原因后保存。封禁/归档会断开该用户连接，正在进行的对局按退出规则处理。归档保留历史，恢复状态可重新启用。
- 物品：可从已有能力模板新增，或复制一件物品再调整。ID创建后固定；名称、数值、属性、能力参数和显示素材可修改。能力必须属于引擎已注册支持的类型，不能上传脚本。
- 角色：维护名称、说明和图片；发布后可在用户编辑中关联。关联角色显示在新对局玩家信息里，HP/MP等仍取模式配置。停用角色后新对局不再显示该外观，旧对局保留快照。
- 素材：支持PNG/JPEG/WebP，最大512KB。上传后自动选中素材；服务端检查文件类型、生成内容哈希文件名，文件保存在 data/uploads。也可使用已有游戏素材。
- 删除：未发布草稿可删除。任何历史版本引用过的物品或角色不能物理删除；编辑为停用并发布。列表禁用删除按钮并提供原因。
- 规则：配置初始资源、手牌和概率；必须满足上限约束。房间内显式选择的末日回合优先于后台默认值。

## 发布

保存内容只会更新草稿。前往“版本发布”，查看每项前后差异，运行预检和3组固定种子测试局，填写版本名称与原因后发布。真正发布前服务器会再次验证，并检查页面核对后是否出现新的草稿变更。

每场对局固定内容版本，物品查询、抽牌、机器人、防御及客户端显示使用同一份内容快照。发布和回滚只影响新对局。回滚不会覆盖编辑中的草稿或回退用户积分。

预检可发现字段、素材、抽取池和部分规则错误，不是穷尽所有组合的兼容性证明。新增复杂能力仍需规则代码、动画与回归测试。

## 权限和记录

超级管理员管理全部模块；用户管理员操作用户/房间；内容编辑修改草稿、上传和测试；发布管理员发布/回滚；只读审计员查询用户和日志。当前管理员不能删除自己或调整自己的权限。

管理员Cookie有8小时有效期；写操作需匹配CSRF令牌和来源，登录失败10次后等待15分钟。开发代理默认允许本机5173来源；自定义部署可通过 ADMIN_ALLOWED_ORIGINS 指定逗号分隔的可信来源，HTTPS部署设置 ADMIN_SECURE_COOKIE=1。

操作日志记录账号、时间、对象、原因及前后差异，不包含登录密码、密码哈希或玩家凭证。权限检查在服务端执行。

## 数据、备份和换电脑

要求 Node.js 22.13 或更新版本。数据在 game/data/game.sqlite，图片在 game/data/uploads；这些都在Git忽略范围内，不会随pull下载。

执行 npm run backup 会使用SQLite一致性快照生成 data/backups/时间戳/game.sqlite，并复制uploads目录。已经在开发环境实际运行过备份命令。

迁移时将备份通过自己的文件传输方式复制到新电脑：先停止目标游戏服务，再将备份里的game.sqlite和uploads目录放入目标game/data，然后启动。不要把备份覆盖到正在运行的数据库，也不要只复制活跃的sqlite主文件而遗漏WAL数据。代码、初始内容随Git同步；用户、管理员改密、草稿和发布记录需要迁移数据库。

原sessions.json仅在首次初始化导入，不会反复覆盖数据库。房间与未结束对局仍驻留内存，重启不恢复；已结束对局摘要保存在数据库。暂无跨进程部署、完整命令回放或外部监控系统。

浏览器已验证指定账号登录、物品搜索/编辑、角色保存与发布预检界面；数据库备份已生成。后续修改应继续运行 npm run typecheck、npm test、npm run build。
