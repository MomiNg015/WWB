# 规则核对（2026-09-19）
 
以原站公开客户端和教典为主要依据，独立实现 TypeScript 规则引擎。未取得原站私有服务端代码，测试通过不等于所有隐藏规则与原版一致。

## 本轮修复

- 按选牌顺序计算攻击、属性覆盖、辉光倍增；精灵道具仅免去紧邻前一张奇迹消耗。首张牌决定攻击类别。
- 前端和服务器共享主动组合与防守合法性；防守不适用卡片直接禁用。主动奇迹可先选牌，零MP点击确认显示原版“MP不足”且不发送命令；追加免耗道具后可以正常提交。机器人遵守同一组合校验。
- 普通盾、反射、乱弹、防止的组合与属性限制；守护神和超常现象不能一概当作武器。
- 购买先揭示随机可负担商品，再由购买者决定接受或拒绝。强制出售按 CP → MP → HP 支付，反射保留原始商品归属。
- 危险杵/臼、升天弓、复活、吸血和梦见之帽共用死亡处理。已有响应与临终攻击完成前不提前宣布胜利；致命交易获得的复活道具立即可用。
- 混乱累计随机行动次数，防御和购买决定仍由本人控制；雾只在有效敌人中改变单体目标；梦境以兼容使用时机的卡片伪装，真实身份不下发。
- 守护神唯一性、地球随机神器、月球奇迹与满月剑组合、非武器响应类别；超常现象目标、晚霞疾病覆盖、磁力风暴等。
- 基础资源上限 99、手牌上限 18；超限接牌先移除已有牌。事件序号保持递增，全体攻击未命中按响应顺序播放。

## 依据

公开客户端：[main.dart.js](https://godfield.net/main.dart.js)，本地研究位于工作区 research/。重点函数包括 tw、l9、la、ev、aN.e1；动画以 A.fl、事件调度以 A.kq 核对。

辅助交叉核对：[超常现象](https://w.atwiki.jp/piong/pages/26.html)、[守护神](https://w.atwiki.jp/piong/pages/27.html)、[梦境](https://macarongamemo.com/entry/godfield-dream)、[梦见之帽与死亡顺序](https://note.com/rich_echium152/n/n3252eae34fe0)。这些资料不是原站服务端实现证明。

## 验证

63 项自动化测试通过，包括所有可主动使用道具的执行检查、各属性下前后端防守一致性、100 组基础机器人对局、30 组九人复杂对局、交易权限和私密投影、真实 Socket.IO 房间流程。类型检查与生产构建通过。

浏览器已操作攻击、防御、反射、安全、零 MP 组合、购买决定与复活测试场景。正式修行联机已验证：攻10对机器人结算后对方HP46；随后对方攻21，使用守5后HP50降至34。

## 仍不能证明的部分

梦境替代卡的概率权重及解除时机、多持有者危险臼的选择分布、极端死亡连锁的原站优先级尚缺充分实战证据。反射链设置了32次保护上限。原站匹配与积分算法不公开，本地匹配和 Elo 为独立实现。详见 research.md。
